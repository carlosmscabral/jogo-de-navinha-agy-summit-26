O objetivo desse repositório é criar um setup para um Jogo de Navinha (Web/JS, com fluxo vertical, de baixo pra cima, com pegada retrô porém visualizações modernas) juntamente com o uso do Antigravity CLI (que será o "construtor" das naves com as quais os usuários vão jogar). Esse setup será executado em um "booth" de evento, o Google Cloud Summit, no qual usuários (não necessariamente especialistas em Antigravity) vão chegar, se registrar em uma interface Web (na qual também teremos instruções, o mais visuais possíveis, sobre o jogo). O cadastro deverá ter o "nome de guerra" do usuário e sua empresa, de forma obrigatória. Deverão escolher, nessa interface Web, servidores "MCP" que terão as ferramentas de construção de sua nave; e sub-agentes pré-definidos (do antigravity) que vão utilizar essas ferramentas (e o prompt do usuário) para a construção da nave - tanto em termos "visuais" como em termos que vão influenciar na mecânica do jogo em si - velocidade da nave, potência e tipos de armas selecionados e outros. A ideia é que da interface Web de registro e seleção, configuremos o harness do Antigravity CLI local. Então o usuário irá ligar o antigravity, que estará habilitado com os servidores/tools MCP e sub-agentes/construtores pré-selecionados e através de um prompt, irá finalizar a criação de sua nave (aspectos funcionais e visuais). Isso feito, a interface gráfica deverá mudar para o modo "jogo", encorporando programaticamente tanto o visual como as características físicas feitas na construção, e partir daí o usuário, através de teclado (simples com setas e barra de espaço para tiros) irá jogar o jogo, com waves e chefão, para atingir sua pontuação. Ao terminar, o sistema deve registrar a pontuação (assuma Firestore no GCP e uma visão Web do leaderboard a ser continuamente exposta em uma tela no booth) e ser completamente resetado para o próximo usuário da fila jogar.

Devemos pensar em restrições/considerações de tempo (quanto tempo um visitante leva no booth?) Não mais que 2/3 minutos por visitante, por exemplo.
Devemos considerar o que deverá rodar localmente na máquina do booth vs o que estará em GCP (podemos ter mais de uma tela, mas num geral, vamos assumir somente uma máquina local)
Vamos assumir que as escolhas de MCP/Sub-Agentes vão influenciar em quão "boa" será a nave durante o jogo - vamos definir quais os parâmetros, etc. Mas o usuário tem que fazer uma escolha balanceada, tendo algum tipo de "budget"- escolher todos os sub-agentes e todos os servidores MCP não deverá ser possível. Idealmente, vamos planejar 3 servidores MCP e 3 Sub-agentes possíveis e planejar alguma mecânica de interação entre eles nas quais boas escolhas/sinergias geram melhores naves. O prompt de construção do usuário também deverá de alguma forma influenciar em uma nave melhor (melhor prompt, melhor nave). Podemos assumir sempre a existência de um sub-agent que vai gerar o visual da nave (que será importado posteriormente no jogo) - e o usuário via prompt poderá também influenciar essa parte visual. Devemos planejar um "hardening" do harness do AGY para que seja focado exclusivamente na construção de naves, de forma o mais determinística possível, e a execução deve claramente indicar que a nave está pronta ao terminar. Uma vez terminada a construção da máquina (potencialmente gerando um JSON em schema pré-definido), a interface Web muda para modo "jogo" e o usuário joga. Os resultados/score devem ser registrados no Firestore e mostrados no Leaderboard. Uma vez terminado o jogo, devemos "resetar" tudo para o próximo usuário - o harness local do antigravity deve voltar para um estado default (um usuário novo irá iniciar uma nova sessão do Antigravity CLI), e um novo usuário começará do zero.
A mecânica do jogo de nave em si deve ser desafiadora - ou seja, espera-se que somente as pessoas com as melhores construções de nave e habilidade no teclado de fato cheguem ao fim. O jogo em si, até o fim, deve levar no máximo 1.5 minutos. Em termos de score, vamos criar um cálculo que privilegia matar mais inimigos, sofrer menos danos (vamos assumir que por padrão a nave pode sofrer 3 tiros antes de morrer, mas eventualmente sub-agentes/tools MCP na construção podem aumentar a vida), terminar mais rápido, etc.... para chegar na pontuação final.
